# zse — Requirements & Rebuild Spec

**zse = Zack Search Engine.** A single-file, client-side "redirect service" that turns short personal aliases into full URLs. Registered as a Chrome custom search engine, so typing an alias in the address bar jumps straight to the target site. No backend — pure HTML+JS hosted on GitHub Pages.

Everything needed to recreate it from scratch lives in this doc.

**Terminology (used consistently in code + docs):** an **alias** is the short key (`ha`, `fdm`). An **argument** is optional text passed after the alias (`fdm https://medium.com/...`). The query param is **`?alias=`**.

---

## 1. Purpose

- Personal, memorable aliases (`ha`, `gm`, `bi`, …) → full URLs (home LAN IPs, web apps, dashboards).
- Optionally pass an **argument** after the alias, substituted into the target URL (e.g. Freedium, search engines).
- Zero infrastructure: one static file, `index.htm`, served by GitHub Pages.
- Doubles as a **human-browsable index page**: visiting the site with no params renders a table of every alias, its description, and its URL.

## 2. How it works today (pre-argument feature)

> This section documents the ORIGINAL behavior for reference. The **proposed design** in §3 supersedes the redirect logic (`?key=` → `?alias=`, first-space argument parsing, `{argument}` placeholder). Section 2.3's `?`-split / `{searchTerms}` logic is **removed** by the new design.

Single file `index.htm`. Three concerns:

### 2.1 Data — the `redirects` map (a JS object literal)
Insertion order matters (drives table render order). Two kinds of entry:

- **Redirect entry** — keyed by the alias:
  ```js
  "ha": {
      url: "http://192.168.3.3:8123/",
      description: "home assistant local"
  }
  ```
- **Separator / section header** — a label row in the table, NOT a real alias:
  ```js
  "Home Assistant": {
      type: "separator"
  }
  ```

Aliases are looked up **case-insensitively**. Multiple aliases may point at the same URL (e.g. `ha`, `hass`, `hal` all → the same Home Assistant local URL).

> **Duplicate-alias caution (ORIGINAL behavior):** a JS object cannot hold two entries with the same key — the last one silently wins and clobbers earlier ones. (History: `amcredit` was accidentally defined twice; the Ecobee entry overwrote the Amazon Credit one until the second was renamed to `ecobee`.) **Superseded by §3.6:** the new parser keys on `(alias, variant-slot)`, so an alias may legitimately appear twice (one plain + one arg row). Same-slot dupes with the *same* URL are ignored; same-slot dupes with *different* URLs are surfaced as a config error rather than silently clobbering.

### 2.2 Render — `window.onload`
1. Grabs `<tbody id="redirectsTable">`.
2. Iterates `Object.keys(redirects)` in **insertion order**.
3. For a `type:"separator"` → bold, full-width (`colSpan=2`) header row.
4. For a redirect entry → a two-column row:
   - **Col 1:** the alias.
   - **Col 2:** the description (grey, small) + `<br>` + the URL as a clickable `<a target="_blank">`.

### 2.3 Redirect — the ORIGINAL `?key=` handler (REMOVED by §3)
1. Read `?key=...` via `URLSearchParams`; no param → show table.
2. Split value on `?`; single token → plain alias redirect; two tokens → look up an alias ending in `?` and substitute `tokens[1]` into `{searchTerms}`.
3. `window.location.replace` after 1 s; miss → "Key Not Found".

> Uses `window.location.replace` (not `.href`) so the redirect page does **not** land in browser history — Back button returns to wherever you came from, not the redirector. **This is retained** in the new design.

## 3. PROPOSED DESIGN — parameterized aliases + `key`→`alias` rename

### 3.0 Summary of changes vs §2
1. Query param **`?key=` → `?alias=`** (new canonical name). **Backward-compat (temporary):** the handler reads `?alias=` first and falls back to legacy `?key=` if `?alias=` is absent **or empty** (uses `||`, not `??`, so a blank `?alias=` doesn't mask the legacy param), so old bookmarks/engines keep working during migration. Marked with a `TODO` to remove the `?key=` fallback later.
2. Argument parsing: split the `?alias=` value on the **first space** — before = alias, after = argument.
3. Placeholder token **`{searchTerms}` → `{argument}`**; old `?`-split logic removed entirely.
4. Per-alias **`raw: true`** flag to opt OUT of URL-encoding (default = encoded).
5. New **orange** "redirecting without argument" state for argument/placeholder mismatches (no hard error; still redirects).
6. Internal variable names use `alias` / `argument` consistently.
7. **Two variants per alias** (§3.6): an alias may define a **plain** URL (no `{argument}`) *and* an **arg** URL (has `{argument}`), selected by whether an argument was typed. E.g. `sf` → portfolio when bare, `/symbol/{argument}` when given a ticker. Same-slot dupes are deduped (URL-only) or flagged as a **red config error**.

### 3.1 Parsing (`window.onload`, end)
1. Read `?alias=<value>` via `URLSearchParams`. No param → show table (index-page mode).
2. `decodeURIComponent` the value first (Chrome `%s` substitution may percent-encode spaces to `%20`), so first-space splitting is reliable.
3. Split the decoded value on the **first space only**:
   - `alias` = substring before the first space.
   - `argument` = substring after the first space (may contain spaces, `?`, `://`, etc. — passed through untouched).
   - No space → `alias` = whole value, `argument` = none.
4. Resolve `alias` **case-insensitively** against the `aliases` map (§3.5). Pick the **variant slot** by argument presence (§3.6): argument typed → prefer the `arg` slot, else fall back to `plain`; no argument → prefer `plain`, else fall back to `arg`. The fallback is what produces the orange cases (§3.2) for single-variant aliases.
   - No match → **red** "Alias Not Found: `<alias>`" box; do not redirect.
   - Selected slot is in **conflict** (same slot defined twice with different URLs, §3.6) → **red** config error naming the clashing URLs; do not redirect.

### 3.2 Argument handling — the 4 cases
Let `U` = the matched alias's `url`, and `hasPlaceholder` = `U` contains the literal `{argument}`.

| # | `{argument}` in `U`? | Argument passed? | Redirect target | Message |
|---|---|---|---|---|
| 1 | No  | No  | `U` as-is | **Green** "Redirecting to `<description>`…" |
| 2 | Yes | Yes | `U` with `{argument}` → argument (encoded unless `raw:true`) | **Green** "Redirecting to `<description>`…" |
| 3 | No  | Yes | `U` as-is (argument dropped) | **Orange** "Redirecting without argument: `<description>`…" |
| 4 | Yes | No  | `U` with the `{argument}` token **stripped** (only the token removed, nothing else trimmed — e.g. `https://freedium-mirror.cfd/`) | **Orange** "Redirecting without argument: `<description>`…" |

- **All four** redirect via `window.location.replace(url)`. Delay depends on the notice: **green (cases 1 & 2) → 500 ms**; **orange (cases 3 & 4) → 1000 ms** (longer so the "without argument" warning is noticeable).
- Unknown alias (§3.1) is the only case that does NOT redirect (red box).

### 3.3 Encoding
- **Default: encoded** — substitute `encodeURIComponent(argument)` into `{argument}`.
- **Per-alias opt-out:** an entry with **`raw: true`** substitutes the argument **verbatim** (no encoding). Required for path-style nested URLs like Freedium.

### 3.4 Config examples
```js
"fdm": {
    url: "https://freedium-mirror.cfd/{argument}",
    raw: true,                                   // insert nested URL unescaped
    description: "Freedium"
},
"g": {
    url: "https://www.google.com/search?q={argument}",   // encoded by default
    description: "Google search"
}
```

### 3.5 Alias data source — inline pipe-delimited block (supersedes the JS object literal)
Aliases are no longer hand-authored as a JS object (§2.1). They live in an inline **`|`-delimited** block for easy editing, parsed at load by `parseRedirects(text)` into **`{ rows, aliases }`**:

- **`rows`** — an ordered list of every authored row, verbatim, used to render the table (so **duplicates are shown as-authored**, and only deduped/flagged at resolve time). Each is `{ type:"separator", title }` or `{ type:"entry", alias, url, description, raw }`.
- **`aliases`** — the **resolution map**, keyed by lowercased alias → a **variant container** (see §3.6): `{ display, variants: { plain?, arg? }, conflict: { plain, arg }, urls: { plain:[], arg:[] } }`. Separators are NOT keys here.

Details:
- **Location:** a `<script type="text/plain" id="redirectData">` placed **near the top of the source** (just inside `<body>`) so it's the first thing an editor reaches — no scrolling past ~370 lines of script. The big logic `<script>` lives at the **end of `<body>`** instead. Inert text (not fetched, not executed), read synchronously at load via `.textContent` — **no extra network request; caching/perf unchanged** vs. the old inline object. End-of-body script placement is also the standard non-blocking position.
- **Parser:** `parseRedirects(text)` (pure, unit-tested). Line grammar (blank lines skipped):
  - `# Section Title` → a separator row in `rows` (title = header text; doubles as a comment line).
  - `alias | url [| description [| raw]]` → an entry row in `rows`, and folded into `aliases` by variant slot (§3.6).
  - **Whitespace around each `|` is optional** — trimmed away, so it may be used for column alignment (`ha | url` and `ha|url` parse identically).
  - 4th field `raw` or `true` (case-insensitive) → `raw: true`. Missing description → defaults to the alias. A line without a url (no `|`) is **skipped** as malformed.
- **Why `|`, not comma:** `|` never occurs in URLs, so **no quoting/escaping is ever needed** (unlike CSV). Chosen for compact, column-aligned, hand-editable rows that preserve order + sections.
- **Order preserved:** `rows` order = authoring order = table order.

### 3.6 Two variants per alias — `(alias, slot)` resolution
An alias resolves on the key **`(alias, variant-slot)`**, not the alias alone. The **slot** is decided by the row's URL:

- **`plain`** slot — URL does **not** contain `{argument}` (used when you pass NO argument).
- **`arg`** slot — URL **contains** `{argument}` (used when you PASS an argument).

So one alias may hold **both** (max two rows). The motivating example — a Seeking Alpha portfolio when bare, a symbol page when given a ticker:
```
sf | https://seekingalpha.com/account/portfolio/summary?portfolioId=65457843 | Seeking Alpha
sf | https://seekingalpha.com/symbol/{argument}                              | Seeking Alpha | true
```
`@`⇥`sf` → portfolio (green); `@`⇥`sf MSFT` → `https://seekingalpha.com/symbol/MSFT` (green). **Two-variant aliases never go orange** — each usage has a matching slot. Single-variant aliases keep the §3.2 orange fallback (bare `fdm` strips `{argument}`; `ha extra` drops the arg).

**Dedup & conflict — keyed on URL only (per slot):**
- Same alias, same slot, **same URL** → **duplicate**: ignored at resolve time (first row wins, incl. its description). **Both rows still render in the table** (dedup is runtime-only, per the owner's choice).
- Same alias, same slot, **different URL** → **conflict**: that slot never redirects; instead a **red config error** names the clashing URLs (e.g. `Config error: alias "sf" (without argument) maps to 2 different URLs: … — …`). Shown **both** in the table (conflicting rows highlighted red, class `.conflict-row`) **and** on navigation to that alias.
- **Conflict is per-slot:** a broken `plain` slot does **not** poison a valid `arg` slot on the same alias (and vice-versa). Only the conflicted usage errors.
- **Max two variants** per alias is enforced for free: a 3rd row in some slot is either an ignored exact-dup or a conflict.

New `resolveRedirect` status: **`conflict`** (alongside `ok` / `noarg` / `notfound`). `conflict` and `notfound` never redirect.

Config/table schema is **unchanged** — no new column. Variants and conflicts are derived purely from the existing `alias | url | …` rows.

Example (whitespace around `|` is cosmetic):
```
# Home Assistant
ha  | http://192.168.3.3:8123/               | home assistant local
# Other
fdm | https://freedium-mirror.cfd/{argument} | Freedium | raw
g   | https://www.google.com/search?q={argument} | Google search
```

## 4. Chrome usage (the whole point)

### 4.1 One-time setup — register as a custom search engine
Chrome → Settings → Search engines → Manage → **Add**:
- **Name:** `zse`
- **Shortcut / keyword:** `@`
- **URL with %s:** `https://zzafarr.github.io/zse/?alias=%s`
  - (Forkers substitute their own GitHub Pages host: `https://<you>.github.io/<repo>/?alias=%s`.)

> These are the owner's live Chrome settings. Any change to the pinned host or the `?alias=` param must be mirrored in `index.htm` (`PINNED_OPENSEARCH_HOST`, `buildSearchUrl`), `opensearch.xml`, and the tests.

> **MIGRATION:** the param renamed `key` → `alias`. Update the Chrome search engine URL from `?key=%s` to `?alias=%s`. During migration this is **not urgent** — the page still accepts legacy `?key=` as a fallback (see §3.0). Once all links use `?alias=`, remove the `?key=` fallback (TODO in code).

### 4.2 Daily use
1. Click the Chrome address bar.
2. Type `@`, press **Tab** (activates the zse engine).
3. Type an alias (optionally a space + argument), e.g. `ha` or `fdm https://medium.com/@x/post`, press **Enter**.
4. Chrome substitutes what you typed for `%s` → navigates to `.../zse/?alias=<alias>[ <argument>]`.
5. Page loads, resolves the alias (+ argument), shows the redirect notice, forwards you after ~0.5 s (green) or ~1 s (orange "without argument").

**Example round-trips:**
| You type | Chrome navigates to | You land on | Notice |
|---|---|---|---|
| `@`⇥`ha`  | `…/zse/?alias=ha`  | `http://192.168.3.3:8123/` (HA local) | green (case 1) |
| `@`⇥`gm`  | `…/zse/?alias=gm`  | `https://gemini.google.com/app` | green (case 1) |
| `@`⇥`sf`  | `…/zse/?alias=sf`  | Seeking Alpha portfolio (plain variant, §3.6) | green (case 1) |
| `@`⇥`sf MSFT` | `…/zse/?alias=sf MSFT` | `https://seekingalpha.com/symbol/MSFT` (arg variant, §3.6) | green (case 2) |
| `@`⇥`fdm https://medium.com/@x/post` | `…/zse/?alias=fdm https://medium.com/@x/post` | `https://freedium-mirror.cfd/https://medium.com/@x/post` (raw) | green (case 2) |
| `@`⇥`g cute cats` | `…/zse/?alias=g cute cats` | `https://www.google.com/search?q=cute%20cats` (encoded) | green (case 2) |
| `@`⇥`ha extra stuff` | `…/zse/?alias=ha extra stuff` | `http://192.168.3.3:8123/` (arg dropped) | orange (case 3) |

### 4.3 Sharing & assisted registration (for forkers)
Goal: let others fork the repo and register their own instance as a Chrome search engine with minimal manual steps. **Fully silent, one-click registration is impossible from a web page** — Chrome has no JS API to add a keyword search engine (anti-hijacking). The page therefore assists two ways, both **auto-detecting the deployment host** from `window.location` (zero config per fork):

1. **OpenSearch auto-discovery** — the page injects a `<link rel="search" type="application/opensearchdescription+xml">` at load. Engine **ShortName is `zse`**. Descriptor source is chosen by `opensearchStrategy(origin, PINNED_OPENSEARCH_HOST)`:
   - **static** — when served from the pinned host (`https://zzafarr.github.io`), the `<link>` points at the checked-in `opensearch.xml` (canonical, reviewable, host-pinned absolute template).
   - **blob** — on any other host (a fork), the descriptor is **generated at runtime** (`buildOpenSearchXml`) from `window.location` and served as a `Blob` URL, so forks need no file edit.
   Chrome then pre-populates the engine under Settings → Search engines; the user still sets the keyword there (Chrome won't do that step programmatically). A unit test asserts the static `opensearch.xml` does not drift from the pinned host / `?alias={searchTerms}` template.
2. **Copy-URL button + inline steps** — a setup panel shows the auto-detected `…/?alias=%s` template (`buildSearchUrl`), a "Copy search URL" button (`navigator.clipboard`), and the 3-step Settings → Add path. Universal fallback; works on any Chromium browser.

Helper functions (pure, unit-tested in `tests/resolve.test.js`):
- `buildSearchUrl(origin, pathname, placeholder)` → strips any filename to its directory + `?alias=<placeholder>`. Placeholder is `"%s"` (manual dialog) or `"{searchTerms}"` (OpenSearch).
- `buildOpenSearchXml(shortName, origin, pathname)` → OpenSearch 1.1 descriptor with an absolute `{searchTerms}` template, `&`-escaped.
- `opensearchStrategy(origin, pinnedHost)` → `"static" | "blob"`; drives whether `buildOpenSearchHref` returns `opensearch.xml` or a runtime Blob URL.

> Considered and rejected: a Chrome extension (needs install + review, and can only set the DEFAULT engine, not a keyword) and enterprise `ManagedSearchEngines` policy (org-managed fleets only). Neither fits "fork a repo and share with friends."

## 5. Editing / deploying

- Edited in-place on GitHub. The map contains a self-referential alias:
  ```js
  "zse": {
      url: "https://github.com/zzafarr/zse/edit/main/index.htm",
      description: "Zack Chrome Redirect Search Engine."
  }
  ```
  so `@`⇥`zse` opens the GitHub editor for this very file.
- Deploy = commit to `main`; GitHub Pages serves `index.htm` and `opensearch.xml` (the latter host-pinned to `zzafarr.github.io`; forks fall back to the runtime Blob descriptor — see §4.3).
- **To add an alias:** add a **`|`-delimited line** `alias | url | description [| raw]` to the `#redirectData` block (§3.5), under the desired `# Section` (order = table order). Whitespace around `|` is optional. Keep aliases unique.

### 5.1 Caching & refresh (GitHub Pages)
- **No `<meta http-equiv="Cache-Control">`** — browsers ignore it for HTTP caching; only real response headers matter. The tag was removed (it previously implied a 1-hour cache that never took effect).
- **GitHub Pages controls caching**, setting `Cache-Control` (~10 min) + `ETag` on responses and allowing **no custom headers**. A true 1-day browser cache is therefore **not achievable** on Pages without a service worker (deliberately not used — keeps the file dependency-free). In practice the browser revalidates via ETag (fast `304`).
- **Refresh procedure (documented, no code):** navigate to a **non-existent alias** (e.g. `?alias=xxx`) so the page renders the red "Alias Not Found" and does **not** redirect, then **Ctrl+Shift+R** (hard reload) to bypass cache. Using an invalid alias (rather than a real one) avoids the 0.5–1 s auto-redirect racing the reload.

## 6. Requirements (to rebuild from scratch)

### Functional
- **R1** Static, single HTML file. No server, no build step, no external JS deps.
- **R2** Aliases authored in an inline **`|`-delimited** `#redirectData` block (§3.5), parsed at load by `parseRedirects` into `{ rows, aliases }`: `rows` = ordered authored rows (entries + `# Title` separators) for the table; `aliases` = the resolution map keyed by lowercased alias → variant container (§3.6). Whitespace around `|` optional. Order preserved. No extra network request.
- **R2a** (§3.6) An alias resolves on `(alias, slot)` where slot = `arg` if the URL contains `{argument}` else `plain`. An alias may define both (max two). Slot chosen by argument presence (prefer matching slot, fall back to the other). Same-slot **same-URL** dupes ignored at resolve time (first wins) but still shown in the table; same-slot **different-URL** dupes → `conflict` status (no redirect). Conflict is **per-slot**. No config/table schema change.
- **R3** Render all rows as a table in authoring order; separators as bold full-width header rows; entries showing alias + description + clickable URL (open in new tab). Rows whose `(alias, slot)` is in conflict are highlighted red (`.conflict-row`); duplicate rows are rendered as-is.
- **R4** Read **`?alias=<value>`** (fall back to legacy **`?key=`** if `alias` absent **or empty**, via `||` — temporary, `TODO` to remove); `decodeURIComponent`; split on the **first space** into `alias` + optional `argument`; resolve alias case-insensitively.
- **R5** Argument substitution: replace `{argument}` in the url. Default **encode** (`encodeURIComponent`); per-alias **`raw:true`** inserts verbatim.
- **R6** Behavior matrix (§3.2), applied to the SELECTED variant: cases 1 & 2 → green notice (`location.replace` after **500 ms**); cases 3 (arg but no placeholder → drop arg) & 4 (placeholder but no arg → strip token) → orange notice (`location.replace` after **1000 ms**); unknown alias → red "Alias Not Found" (no redirect); conflicted slot (§3.6) → red config error (no redirect).
- **R7** Multiple aliases may map to the same URL. An alias key may appear at most twice — once per variant slot (§3.6, R2a); any further same-slot row is an ignored dup or a conflict.
- **R8** Use `location.replace` (not `.href`) to keep the redirector out of history.
- **R9** Assisted registration (§4.3): auto-detect host from `window.location`; inject an OpenSearch `<link>` (runtime-generated Blob descriptor); show a copy-URL button + inline setup steps. No static per-fork config.

### Non-functional
- **N1** Works as a Chrome custom search engine via a **`?alias=%s`** URL template.
- **N2** No tracking, no analytics, no cookies; entirely client-side.
- **N3** Self-editable: include a `zse` alias linking to this file's GitHub edit URL.
- **N4** Reachable on LAN targets (plain-`http://` private IPs are fine — this is a personal tool).
- **N5** Consistent naming: code uses `alias` and `argument` throughout (no `key`/`searchTerms`).
- **N6** Forkable/shareable: a forked repo works with zero code edits beyond the `redirects` map — host is auto-detected, no `opensearch.xml` to hand-edit. README documents fork → Pages → register flow.
- **N7** Caching: no reliance on `<meta>` cache directives; caching is whatever GitHub Pages provides (ETag revalidation). No service worker. Refresh procedure documented (§5.1).

## 7. Known limitations / gotchas

- **L1** All aliases and URLs are **public** — repo `zzafarr/zse` is confirmed PUBLIC (verified via `gh repo view`), so `index.htm` and every URL are world-readable at `github.com/zzafarr/zse` and served publicly by GitHub Pages (free-plan Pages are always public regardless of repo visibility; access-controlled Pages need Enterprise Cloud). The Nabu Casa remote HA URL (`…ui.nabu.casa/`) is therefore an effectively-public secret. **Accepted risk (owner's decision):** URL kept in the map as-is. Do not add higher-value secrets/tokens.
- **L2** Chrome `%s` substitution may percent-encode the typed text (spaces → `%20`) before the page sees it; the parser `decodeURIComponent`s the `alias` value first so first-space splitting works.
- **L3** With `raw:true`, the argument is inserted with zero sanitization — a malformed argument yields a malformed target URL (acceptable for a personal tool).
- **L4** Cosmetic: `.redirect-message` (green) currently has a pale-orange left border (mismatched); the orange "without argument" state should have a coherent orange scheme; `.no-match-message` red.
- **L5** Duplicate aliases silently clobber — see §2.1.
- **L6** The `{searchTerms}` placeholder and `?`-split logic are removed. The `?key=` param is **temporarily still accepted** as a fallback for legacy links (§3.0); it is slated for removal (`TODO` in code) — migrate links/engines to `?alias=`.
- **L7** A true 1-day (or any custom) browser cache is **not achievable** on GitHub Pages — it forces its own `Cache-Control` (~10 min) + `ETag` and forbids custom headers; `<meta>` cache tags are ignored. Only a service worker could give real long-lived caching (not used here). See §5.1.
- **L8** Variant slots (§3.6) are inferred **only** from the presence of the literal `{argument}` in the URL — there is no explicit marker. So a plain URL that happens to need a literal `{argument}` substring can't be authored (acceptable: no real URL contains it). Max two variants per alias; a 3rd same-slot row is silently deduped (if identical URL) or turns the slot red (if different) rather than being a distinct third target.
